# ADR-0007：文档级受控线上 A/B

## 状态

已采纳（2026-10-04）。本决策约束后续实现，不表示线上能力已经部署或允许开启真实实验。

维护者确认详细方案后进入 Phase 6。此前未发布的实现及阶段完成记录已废弃；本决策独立定义新契约，不沿用旧实现的授权或验证结果。

## 背景

离线 Experiment 用同一冻结输入比较不同 Prompt，强制 ISOLATED。真实任务输入不同、涉及草稿和人工审批，不能通过解除离线隔离得到线上实验，也不能把最终审批通过等同于 Agent 原始输出质量。

现有 Task 与 AgentExecution 一对一、冻结输入、Capability、Token 账本、版本乐观锁和 ChangeRequest 审批继续作为基础。线上增加分配与评价归属，不新增独立 Run，不改重跑/返工语义。

精确协议见 [受控线上 A/B 契约](../controlled-online-ab-api-contract.md)，可复现向量见 [协议样例](../fixtures/controlled-online-ab-v2.json)。

## 决策

### 1. 一文档一组，一个 Space 一个运行占位

- 同一 Agent 的 baseline 和一个 Prompt candidate 使用不可变配置模板，只允许系统 Prompt 不同；ALL_BOUND、无外部 MCP、无跨任务记忆/会话共享。
- 系统生成一次随机 seed，以 documentId 稳定分桶；目标比例是文档分组概率，实际 Task 比例另列。
- 同 Space 最多一个 ACTIVE/PAUSED/STOPPING 实验，允许多个 CREATED 草案；STOPPED 才释放占位。此限制不改变普通 Task 并发或 Space Redis 投递锁。
- 只分配范围内新 ORIGINAL + LIVE Task。重复 RPC/MQ 恢复同一身份；RERUN、REVIEW_REWORK 不参与，继续 ADR-0001 的当前 Agent 配置语义；REPLAY/EXPERIMENT 保持隔离。

### 2. 新输入与线上证明独立于历史候选

现有 AgentCandidateConfig 必须绑定历史 source Task/Execution，旧 Prompt hash 还包含来源指令，不能当作当前配置模板直接用于新 LIVE。

Agent 领域保存两条 agent_online_config 模板，使用已有配置捕获、Prompt 构建和快照规范化原语，冻结当前 Agent/模型/Skill/工具及实际依赖；不放宽历史 CandidateConfig 的非空来源或恢复校验。

线上 manifest、模板、binding、分桶及报告采用独立 schema 2，拒绝旧线上 schema 1 身份自动升级。Input Snapshot v1 与 Execution Snapshot v3 仍按既有契约；新的指令/版本在创建时冻结，执行准备重新形成 Prompt 与 execution hash。

Task Capability 同时绑定资源/action 与 online binding hash。两条 Runtime、Auth、Task、Document、Gateway 及终态恢复都核验线上身份；离线 Worker 不因新增能力获得 LIVE 权限。

### 3. 原子门禁、预算与执行槽

Task 先保存幂等创建意图，Evaluation 在单实验短事务中分配顺序、组别、预算和 binding。请求/响应丢失复用原 Task/assignment，模型/RPC 不在数据库事务或 Space 锁内。

总授权、最大 Task 数及单 Task 预算在启动前明确冻结。准入使用实际已结算 + 未结算预留 + 本次上限；未知不按零结算，不能人工修改账本腾预算。在途调用仍可能超额，实际、未知、预留与超额分别展示。

两组各一个数据库权威执行槽。槽覆盖取得准入到权威执行终态，排队不占槽；同 Task 幂等占用。失联/超时不是释放证明，未知暂停并对账。执行槽可因权威终态释放而账本预算继续未决，不能把两者混成一种租约。

### 4. 正常停止与紧急熔断

正常停止原子关闭新分配，在途按冻结身份收敛。紧急熔断另禁止已接受但未开始项执行，并尽力取消活跃实验 Task；取消请求与远端确认分开，未知仍占位。

预算超额、确认越权/证明矛盾、安全事件触发熔断；余额耗尽、依赖漂移、完整健康窗口异常、对账未决和可信 SRM 异常按冻结保护策略暂停。保护动作不自动产生质量结论。

暂停/停止的新普通任务返回当时正常生产配置，不承诺与冻结 baseline 一致。已发生费用、草稿、审批和正式版本不可自动撤销。PAUSED 可明确 stop，不按时间强制释放未知占位。

授权或文档归属失效时，冻结输入不构成永久授权；未开始项拒绝，已开始项停止新的受保护动作并请求取消，不能继续跨空间读写。

### 5. 文档级描述性分析

每文档最早 accepted assignment 为主分析入口，不选择第一个成功 Task；Task 级成本/成功率/延迟另作运行描述。同文档多次调用不扩大独立文档数。

主指标是首任务未经审批修改的原始产物可交付率，规则版本、expected、阈值与适用映射预注册。输出 PASS/FAIL/MISSING，同时显示有效分母、全部分配分母与已证实覆盖；失败/取消/缺失不从总体剔除。

描述性完整性门槛固定为每组至少 30 个参与文档、主指标有效覆盖至少 80%；人工质量为必要依据时，选定盲态有效覆盖每组至少 80%。MDE 以绝对比例差记录，默认讨论值 0.1，启动前必须明确业务理由；默认分配 7 天、追加观察 48 小时。门槛不等于功效设计。

各组文档级比例提供 95% Clopper–Pearson 区间，不提供组间显著性、因果提升或自动赢家。SRM 使用独立的分配诊断，不是效果检验；小样本做协议核查，不能报告统计诊断通过。

### 6. 原始输出、审批与盲态分层

保存审批前原产物身份/hash 和受控引用，审批修改/正式结果单列；只在原提案与最终版本可比时计算固定编辑差异，不拿审批后的质量代替原质量。

既有 text-assertion 只读 resultSummary，继续原语义。新增窄的 online-original-text-assertion / online-document-change-validator 与发布版本，消费合法 LIVE 原始证据，不伪造摘要或隔离 Artifact。

每文档首产物全量邀请评价，默认隐藏组/Prompt；BLINDED/NON_BLINDED/UNKNOWN、首评/更正、已评/未评分层。0–4 rubric 映射既有 0–1 score，不改变历史人工分数。

普通比较结论的样本/覆盖门禁在服务端强制。确认安全事件可独立 REJECTED 止损，但普通低评分不能冒充安全例外。ACCEPTED 仅表示值得继续验证，不是上线批准。

### 7. 权限、审计与保留

管理必须是当前 Space 受保护 OWNER，并具有相应 evaluation/agent/task 动作；不把平台管理员或创建者视作 OWNER。普通发起人的文档动作不扩大，正式审批依旧独立。

人工反馈沿用 evaluation:run，不引入不存在的 evaluation:feedback 权限。资源下钻复查 Task/Document 授权，概要不泄露正文；任务创建前披露试验和真实副作用。

快照、账本、审计和 OTel 保持各自权威边界。报告 revision 追加不可变，结论固定 revision；Trace 缺失不解释为无执行。证据不新增自动 TTL，部署先确认容量/删除处理责任；撤权或删除后准确提示不可读，不宣称 hash 可恢复正文。

### 8. 迁移与部署

V30 作为已执行历史恢复保留，Flyway checksum 为 -1400201146，不修改、不重新执行来模拟新设计。新结构从 V31 向前调整，特别将旧 Space/Agent 占位升级为 Space 唯一占位，并建立独立创建意图、执行槽与新模板身份。

升级前检查旧在线记录、占位冲突及主体完整性。旧 schema 不自动获得新执行能力；有旧数据时停在明确的升级/归档处理门禁，不删除历史。空库与 V30 升级均纳入验证。

先迁移、兼容读/拒绝未知 schema 的服务，再验证分配/限额/对账与 UI，最后由 OWNER 对具体范围/额度开启。回退先停止/熔断并确认无未决执行、预算和占位；不直接启动不能理解线上主体的旧扫描器。

## 未采用方案

- 按 Task 随机分组：同文档跨组写入容易混淆归因，首版选择文档稳定组。
- 直接复用离线运行或历史 CandidateConfig：会混入旧输入或放松隔离/来源证明。
- 只统计完成 Task、取消样本剔除、自动提升候选：会制造选择偏差或绕过人工配置决策。
- 执行锁覆盖整个 Space、独立资源集群、通用信号量/预聚合平台：超出本阶段需要，采用最小组级准入与已有调度。
- 超时自动释放未知预算/槽/Space 占位：远端仍可能执行，无法证明安全。

## 影响与验证

新增线上分配/模板/意图/执行槽及报告主体，保持 Run 一对一、离线报告和权限语义。代价是未知执行时宁可暂停占位，且首版只能提供描述性证据。

正式契约和公开 fixture 验证 canonical/hash、长 ID/Unicode/seed、桶边界、SRM/区间、规则与反馈门禁。后续再验证 MySQL 5.7 升级、双实例竞态、停止/熔断、真实草稿/审批与页面；本 ADR 的采纳不替代这些实现验收。
