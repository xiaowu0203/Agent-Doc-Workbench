# v0.1.0 升级至 v0.2.0：数据库与回退

> 发布准备草案：V22→V44 迁移与备份恢复已在 MySQL 5.7 合成样本上验证；完整服务部署、所有历史数据形态和上线后写入的回退尚未验证。正式发布前须重新核对本文及部署步骤。

## 适用范围

本指南适用于使用 v0.1.0 正式 V1～V22 Flyway 基线、准备升级至包含 V23～V44 的 v0.2.0 代码的环境。更早的开发库可能使用不同迁移历史或 checksum，必须先单独评估；不要修改 V1～V22 或删除 Flyway 历史来绕过校验。

V23 涉及 Task/AgentExecution 血缘及 Token 账本，MySQL DDL 会自动提交。**使用维护窗口，禁止新旧版本服务混合写入；不要把数据库事务回滚当成迁移回退。** Auth Service 托管 Flyway，须先完成迁移，再启动使用新结构的服务。

## 升级前

1. 确认目标版本、MySQL 5.7、数据库连接及 Flyway 状态；盘点运行中任务、审批和对账。暂停外部写流量，停止所有业务写入并记录未完成任务，避免旧服务在迁移期间写入。
2. 对数据库及其他需恢复的持久化资源执行备份；在独立环境恢复并核对可读取性和关键数据。验证备份包含表结构、数据及所需存储过程、触发器和事件，并记录备份时点。不要对业务库直接进行恢复演练。
   隔离演练必须同时隔离数据库、Redis、消息队列及对象存储：不要让指向空库或数据副本的 Agent 使用原环境的 MinIO Bucket。Skill 孤儿清理依据当前数据库判断对象引用，混用 Bucket 可能删除原环境仍在使用的文件；演练需要的对象应从备份复制到专用 Bucket。
3. 在 V22 目标库执行 [V23 预检](v23-readonly-precheck.sql)。脚本只读取业务表，但使用会话级临时表；必须在**同一个交互式 MySQL 会话分段执行**。第 5 节反复执行 UPDATE 至未完成行数为零，再查询结果并删除临时表；不能把整个文件一次性输入客户端后就认为父链检查完成。
4. 审查预检结果。一对一关联、重改关系/审计及异常父链应在升级前人工评估和处置；无关联历史 Token、缺少历史价格快照、没有重试审计的派生任务是信息性结果，记录并核对，不伪造缺失事实。预检异常未处理完成时不继续升级。
5. 准备统一版本的服务配置及密钥；尤其确认 JWT 公钥地址、MySQL、Redis、Task 与 Evaluation 的 Capability 加密密钥。自动首次报告还需要 Agent 和 Evaluation 配置相同的独立 `EXPERIMENT_REPORT_PROOF_KEY`（Base64 编码至少 32 随机字节）；Evaluation 通过 `AGENT_INTERNAL_URL` 直连 Agent，跨主机必须使用受信任的加密网络并保持时钟同步。未配置或配置不一致时后台报告会拒绝生成，人工重算仍使用用户授权。Evaluation 默认读取 `MYSQL_*`、`REDIS_*`、`AUTH_JWKS_URL`；显式 `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` 覆盖共享数据库配置。密钥通过受信任的环境或密钥管理系统提供，不写入仓库和日志。

## 迁移与检查

1. 保持业务写入关闭。启动目标版本 Auth Service，由 Flyway 顺序执行 V23～V44；检查每个版本均有成功记录，并确认 Flyway 校验无误。若迁移失败，停止继续启动和写入，保存日志及当前状态，按下述恢复方式处理。
2. 迁移成功后启动同一版本的 Document、Task、Agent、Evaluation 和 Gateway，核对健康状态、内部地址与数据库/Redis 连接。先进行只读检查，再按授权执行专用样本的端到端烟测。
3. 核查历史文档及版本、Task 血缘与模式、执行快照和账本，抽查下列计数：

```sql
SELECT COUNT(*) AS invalid_task_semantics
FROM task WHERE root_task_id IS NULL OR lineage_type IS NULL OR execution_mode IS NULL;

SELECT COUNT(*) AS duplicate_execution_ledger
FROM (SELECT execution_id FROM token_usage_detail WHERE execution_id IS NOT NULL
      GROUP BY execution_id HAVING COUNT(*) > 1) duplicates;

SELECT COUNT(*) AS legacy_unattached_token_rows
FROM token_usage_detail WHERE execution_id IS NULL;
```

前两项应为零；无执行身份的历史账本行允许保留为空，须记录数量，不应补造关联。还需核对实际价格快照、异常血缘及审批记录；上述查询不是完整验收清单。

4. 核对用户权限、冻结文档读取、Replay 隔离与正常任务链路，并确认没有意外外部副作用。完成验证和人工放行后再恢复写流量。

## 失败与回退

- **尚未执行迁移**：确认数据库和业务写入状态后，可按原环境恢复服务。
- **迁移失败或成功但尚未恢复写入**：保持写入停止，保留诊断信息；将升级前备份恢复到独立数据库，核验后再配合旧版本服务切换。不得只删除 `flyway_schema_history` 记录并重跑。
- **新版本已接受写入**：优先前向修复。回退旧备份会丢失备份后的写入；确需回退时先停止写入、保存新数据，并制定和验证单独的数据转换与补录方案。旧服务不能直接写入已升级的 V23+ 数据库。

保留备份、恢复校验、预检结果、迁移版本、烟测及恢复流量决策记录，供故障排查和审计。
