# Agent‑Doc‑Workbench 项目完整开发规划文档

> **基线说明（2026-08-24）**：本文保留早期产品规划，其中关于“仅 MCP Client”“v0.1 不实现 A2A”以及 Agent 合并在 task-service 的描述已被 Phase 3 实现取代。当前架构以 [`docs/agent-server-a2a-mcp-design.md`](agent-server-a2a-mcp-design.md) 和 [`docs/PHASE3-HANDOFF.md`](PHASE3-HANDOFF.md) 为准：`agent-service` 提供 A2A Agent Server，`task-service` 提供 A2A Client 与 Workbench MCP Server。

## 一、项目基础概述

### 1.1 项目名称

Agent‑Doc‑Workbench：面向个人 / 小团队的 Agent 活文档协作开源 Web 工作台

### 1.2 核心项目定位

开源轻量 Web 协作工作台，主打**文档作为 AI Agent 任务唯一协作载体**。

> 核心范式：
>
> 1. Agent **禁止直接改写正式文档**，所有修改统一生成 Diff 变更请求，经人工审核、批注、确认后才可合并生效；
> 2. 原生遵循 MCP 协议，仅作为 MCP Client 对接任意外部 Agent；**本项目不自托管、不运行任何大模型推理**；
> 3. 自带多层 Token 预算熔断机制，解决个人 / 小团队多 Agent 成本失控问题。

迭代核心策略：

**v0.1 MVP 仅实现单 Agent 能力，多 Agent 编排、A2A 能力后置至 v0.2 迭代，严控初期开发复杂度，快速落地可用开源版本。**

目标用户：独立开发者、小产品团队、内容创作团队、小型研发团队。

> 明确排除：不做重型企业多租户知识库、不面向大型政企组织、不做完整低代码 Agent 编排平台。

### 1.3 核心差异化优势

- **对比 Notion AI / WPS AI**：摒弃 AI 直接改写文档模式，Agent 改动全链路可追溯、可审核、可回滚，解决 AI 无脑改稿、内容不可控问题。
- **对比 LangGraph / CrewAI 等编排框架**：不再是内存内临时任务输出，提供可视化持久化文档协作载体，Agent 任务过程、变更、版本永久沉淀。
- **对比各类 AI 文档开源项目**：独有「草稿 / 正式双文档模式」+「多层 Token 预算熔断」+「MCP 通用适配」，精准解决个人小团队两大痛点：**成本失控、AI 输出内容不可控**。

### 1.4 技术总览与架构约束【新增章节】

> 对齐微服务设计，用于开发团队统一认知，避免实现偏离。

1. 整体架构：Spring Cloud 微服务架构；区分业务微服务 + common 聚合模块（技术 starter + 业务契约 SDK）。

2. 模块划分

  - `auth‑service`：用户账号、认证、JWT 签发；

  - `gateway‑service`：WebFlux 网关，请求入口、JWT 解析透传、路由转发；仅依赖基础 core 包，不引入任何业务 / ORM/MQ starter，不执行业务逻辑；

  - `document‑service`：空间、成员权限模型、文档树、文档存储、版本快照、Diff 生成、权限校验 Feign 接口；

  - `task‑service`：Agent 实例管理、MCP 客户端、异步任务调度、变更审批队列、Token 用量统计、审计日志；

  - ```
     common
     ```

    聚合工程：

    - `common‑core`：基础 POJO、基类、通用工具、异常、注解；全部服务必依赖；
    - `common‑agent‑sdk`：Agent 相关 DTO、Feign 契约接口；**仅契约，无业务实现，为 v0.2 Orchestrator‑Worker 做预留**；
    - 若干`xxx‑spring‑boot‑starter`：纯技术基础设施（web /springdoc/mybatis‑plus /redis/feign /mq/oss /sentinel/monitor）；**不存放任何业务 Controller/Service/Entity**。

3. 演进约束

  - v0.1：**禁止实现 A2A、流水线、编排引擎**；数据库可预留扩展字段，但不编写对应业务代码；
  - MQ 作为任务异步载体，MCP 调用全部异步化，禁止同步阻塞 HTTP 调用外部 Agent；
  - 审计日志只允许 Insert，业务层禁止 Update / 物理 Delete。

4. 外部依赖约束：v0.1/v0.2 只作为 MCP Client；v0.3 才对外暴露本平台 MCP‑Server 能力。

## 二、全量业务功能清单

### 2.1 空间与文档管理系统（基础核心）

#### 2.1.1 工作空间能力

- 默认个人私有空间，支持创建多套小团队协作空间（适配 2‑10 人小团队，无复杂企业组织架构）

- 精细化成员角色权限体系：角色绑定到

  具体空间

  ，不属于用户全局属性

  - `OWNER` 所有者：全权管理，配置 Agent 凭证、全局 Token 预算、成员权限、空间设置
  - `EDITOR` 编辑者：编辑文档、发起 Agent 任务、审批 Agent 变更请求
  - `VIEWER` 观察者：仅只读查看，无任何编辑、审批、操作权限

- 空间全局配置：

  - 全局 Token 总预算；
  - Agent 最大并发上限（配置字段 v0.1 入库预留，v0.1 逻辑串行，v0.2 正式生效）；
  - MCP 服务基础配置；
  - 空间维度工具白名单管控。

#### 2.1.2 文档核心能力

- 树形文件夹管理，支持多级目录、文档分类、自定义标签、文档描述备注
- 核心双文档模式（核心亮点）
  - 草稿文档：试错专用，Agent 可直接自由编辑、无需审批，快速迭代内容，无变更审核流程
  - 正式文档：成果沉淀专用，**所有 Agent 修改必须生成 Diff 变更请求，人工审批通过后方可合并生效，Agent 无直接写入权限**
- 文档基础能力：创建、删除、重命名、移动、归档、回收站恢复
- 文档版本快照：每次合并变更自动生成版本记录，支持一键回滚任意历史版本；回滚生成新版本，不删除历史快照。
- 文档分享：支持生成只读公开分享链接，便捷对外分享成果。

> 非功能约束：大文档不强制全量加载；MCP 调用支持片段读取文档，减少 Token 消耗。

### 2.2 编辑器核心能力

- 基于 ProseMirror + Yjs 构建富文本编辑器，底层原生存储 Markdown 格式，双向无缝兼容
- 基础编辑能力：标题、多级列表、表格、代码块、图片、超链接、文本样式调整
- Diff 差异可视化审批（核心功能）
  - 精准展示 Agent 变更的新增、删除、修改内容，高亮差异化展示
  - 审批操作集合：全部接受、部分接受、修改后接受、拒绝变更、添加批注退回 Agent 重改
  - 每条 Diff 自动绑定对应 Agent 身份、关联任务 ID、操作时间，全程溯源
- 多人协同编辑：v0.1 简化为非强实时轮询同步，降低开发难度；v0.3 再优化实时协同。
- 文档片段批注能力：支持人工对指定段落批注，精准指派 Agent 针对批注内容迭代修改。

### 2.3 Agent 协作能力（核心业务）

#### 2.3.1 通用 Agent 基础体系

> Agent 不是人类用户账号；属于可配置外部 MCP 执行器资源，鉴权依靠绑定空间 + 工具白名单，不使用用户登录身份。

- Agent 元数据：名称、头像、简介、MCP 服务端点、绑定模型、启停状态、月度 Token 配额。
- 权限管控：限定 Agent 仅可操作指定空间 / 文件夹，禁止跨空间越权访问。
- 原生 MCP 客户端：兼容任意外部 MCP Server，支持本地 / 远程 Agent 接入，无模型绑定限制。
- 工具白名单机制：可手动限制 Agent 可调用的工具集合，规避越权操作风险。

#### 2.3.2 Agent 任务生命周期管理

- 完整任务实体属性：任务名称、目标描述、提示词、关联文档、Agent 实例 ID、执行状态、Token 消耗、运行日志、单任务 Token 上限。
- 任务状态枚举：`PENDING待运行、RUNNING运行中、COMPLETED已完成、TERMINATED已终止、FAILED异常失败`。
- 人工可控：支持手动暂停、终止运行中的 Agent 任务，防止无效 Token 消耗。
- 双执行模式与文档类型强绑定
  - 草稿文档：Agent 直接编辑执行，无审批流程，快速试错
  - 正式文档：Agent 仅生成 Diff 变更请求，进入审批队列，**不直接修改文档内容**

> ⚠️v0.1 刚性约束：一个任务仅绑定**单个 Agent 实例**；不支持 Agent 调用 Agent (A2A)、不支持编排、不支持流水线。
>
> 数据库预留`parent_task_id`字段用于未来父子任务，v0.1 业务逻辑不使用此字段。

#### 2.3.3 版本能力限制规则

- **v0.1 MVP**：仅支持单 Agent 串行执行；同一空间同一时刻只允许运行一个 Agent 任务，无并行多 Agent 能力。
- **v0.2 迭代**：新增 Orchestrator‑Worker 多 Agent 分工模式，**需要用户手动开启开关**；开启前 UI 弹窗提示 Token 成倍消耗风险。

### 2.4 Token 成本管控系统（核心差异化、刚需能力）

专为个人 / 小团队设计，解决多 Agent Token 消耗失控、账单不可控。

> 三层熔断优先级（任意条件触发，任务终止，记录审计日志）
>
> 1. 任务级：单任务最大 Token 上限；
> 2. Agent 实例级：Agent 月度配额；
> 3. 空间级：空间全局总预算。

- **任务级预算管控**：启动 Agent 任务前，可自定义单任务最大 Token 上限，到达阈值自动终止任务。
- **多维度用量统计**：按空间、文档、任务、单个 Agent 四大维度，统计输入 / 输出 Token、预估消耗成本。
- **全局熔断保护**：空间总预算耗尽，禁止新 Agent 任务启动。
- **模型分层适配**：不同 Agent 可绑定不同大模型，简单任务使用廉价模型，复杂任务使用高阶模型。
- **风险提示机制**：开启多 Agent 高级模式前，强制弹窗提示 Token 消耗风险，用户确认后才可启动。

> 技术约束：Token 消耗为异步落库；依靠 MQ 保证用量记录尽量不丢失，设计死信兜底。

### 2.5 变更审批与审计日志系统

- 统一变更审批队列：所有正式文档的 Agent 修改全部聚合至队列，支持批量审批处理。
- 全链路溯源审计日志：记录操作主体（人 / Agent）、操作类型、操作时间、关联文档、关联任务 ID、变更摘要、TraceId。
- 安全约束：审计日志只做新增，业务逻辑禁止更新、物理删除；满足小团队基础合规溯源。
- 版本迭代：v0.1 仅日志展示；v0.2 新增日志 JSON/Markdown 导出能力。

### 2.6 导入导出与外部集成能力

- 文档导入导出：支持 Markdown 单文件导入导出、整文件夹批量导出。
- 基础 REST API：支持外部程序创建文档、下发 Agent 任务、读取变更记录、查询用量数据。
- 迭代规划：v0.3 对外暴露 MCP Server，支持 LangGraph、CrewAI 等外部 Agent 框架调用本工作台能力。

### 2.7 辅助配套能力

- AI 任务提示词模板库（v0.2 上线）：预置 PRD 撰写、调研报告、技术方案、内容润色等模板，支持自定义保存复用。
- 站内消息通知：Agent 提交新变更、任务完成 / 异常实时站内提醒（v0.1 不做邮件、短信通知）。

## 三、v0.1 MVP 明确不做范围（严控复杂度）【强化刚性】

> 下面列表内，v0.1**不开发业务逻辑**，仅允许做数据库字段预留；禁止为未来功能提前编写业务代码，避免范围蔓延。

1. ❌ 不做多 Agent 并行协同、A2A Agent 调用、流水线编排、Orchestrator 调度能力（延后 v0.2）
2. ❌ 不自托管、不自部署大模型推理服务，全程依赖外部 MCP / 第三方模型
3. ❌ 不做大型企业多租户、组织架构、部门层级体系
4. ❌ 不支持 Excel、PPT 解析渲染，专注 Markdown 文档核心场景
5. ❌ 无邮件、第三方 IM 深度集成能力
6. ❌ 无复杂企业合规导出、企业级风控，仅适配小团队基础审计溯源
7. ❌ 不对外暴露平台 MCP‑Server（v0.3）
8. ❌ 提示词模板库、站内消息通知延后 v0.2

## 四、风险与规避【新增章节，开发必读】

|           风险           |                  描述                  |                           规避方案                           |
| :----------------------: | :------------------------------------: | :----------------------------------------------------------: |
| MCP 外部服务不稳定、超时 |   调用外部 Agent 网络异常，任务卡死    | MQ 异步，设置超时时间；任务状态标记失败；支持手动终止；死信消息记录异常任务 |
|      Token 超额消耗      |        Agent 无限输出，成本飙升        |       三层熔断；任务超限立即终止；审计日志记录熔断事件       |
|       权限越权风险       |   Agent 越权访问不属于绑定空间的文档   | Agent 配置仅维护绑定空间 ID 集合；**文档‑service 统一做最终权限判定，task‑service 不能跳过权限校验** |
|       异步消息丢失       | 任务结束，Token 用量、审计日志没有落库 | MQ 持久化、重试、死信队列；尽量消费成功之后再完成业务状态更新 |
|         范围蔓延         | 开发阶段提前引入 v0.2 编排 / A2A 逻辑  | 文档刚性约束 v0.1 能力；代码 Review 检查，禁止提前实现未迭代功能 |
|    审计日志被篡改删除    |         业务逻辑误操作审计记录         |   数据库层禁止 update/delete 审计日志；应用层只允许 insert   |

## 五、版本迭代里程碑规划

### 4.1 v0.1 核心底座版本（可开源发布）

核心目标：跑通完整人机协作闭环，形成可用、稳定的开源基础版本

覆盖能力：空间文档管理、双文档模式、ProseMirror 编辑器、单 Agent MCP 接入、Diff 审批流程、多层 Token 预算熔断、审计日志、基础导入导出、REST API。

### 4.2 v0.2 功能增强版本

核心目标：提升协作效率，拓展场景，优化成本控制

新增能力：按需开启 Orchestrator‑Worker 多 Agent 分工协作、docx 文档导入导出、提示词模板库、审计日志导出、审批批量操作优化。

> v0.2 重点解决：A2A 场景下身份继承、子任务 Trace 链路串联、总任务统一 Token 预算、防循环调用。

### 4.3 v0.3 生态扩展版本

核心目标：打通外部生态、提升性能、拓展场景边界

新增能力：对外暴露 MCP Server、Excalidraw 绘图嵌入、超大文档渲染性能优化、第三方生态适配优化。

## 六、核心业务完整闭环（v0.1 可演示）

1. 用户创建个人 / 团队空间，新建**正式文档**，手动录入基础内容与框架。
2. 在 Agent 管理页面配置外部 MCP Agent 连接，设置单任务 Token 预算阈值，基于文档下发任务。
3. Agent 通过 MCP 协议按需读取文档片段（不加载全文，减少 Token），生成内容修改。
4. Agent 提交 Diff 变更请求，进入审批队列，页面可视化展示增删改差异。
5. 人工精细化审批：部分接受、修改后确认、拒绝无效变更、批注退回重改。
6. 审批通过后，变更合并至正式文档，自动生成版本快照；同步记录 Token 消耗与审计日志。
7. 试错迭代场景：复制文档至草稿区，允许 Agent 自由编辑调试，无需审批，降低协作成本。
8. 任务完成后，可导出 Markdown 成果、查看完整用量统计；随时可手动终止闲置任务，避免无效消耗。
