## 1. 已确认的产品政策

- 单实例 Keycloak（测试 H2/正式独立 PostgreSQL）+ 薄 Gateway BFF；单应用 realm、必要 mapper，不建设集群/复杂联邦。
- 业务权限全部由对应业务服务判断，BFF 不实现租户/空间/Capability/Skill/ACL 规则。
- 新增 local 简易账号模式，无需 Keycloak/PG；启动配置选择，不自动故障回退，切换必须重启并清理旧模式会话。具体契约仍待 PoC。
- Access Token 7 天；BFF 空闲上限/绝对上限均为 7 天。
- 保留“记住我”：勾选使用最多 7 天的持久 Cookie，不勾选使用会话 Cookie；均不延长首次登录的服务端绝对截止。
- oidc 为 IdP 建账号、管理员预绑定；local 为本地管理员建账号/设置密码。首版关闭公开注册，oidc 另关闭 JIT。Workbench 保留展示资料、部门和业务权限。
- 默认仅退出当前 Workbench；oidc 另有显式 SSO 注销入口，local 不展示 SSO 操作。

这些决定不表示 7 天 Access 的副本会随本地注销立即失效。普通 JWT 离线验签仍可能接受未过期副本；本地启停/撤销与 IdP 会话策略必须分别实现和验收。

## 6. 当前P0最小入口止损

- 两个签发入口及Agent执行档案只接受独立Task机器凭据；普通用户Bearer、匿名、错机器主体/凭据与重复Authorization拒绝。公共Gateway在白名单/OPTIONS前拒绝这些内部路径及编码变体。
- 现有Feign契约仅在上述三个调用分支改用受控直连，剔除用户及Task/恢复/线上凭据；普通用户契约保持原路径。真实Feign契约测试验证了目标URL与头隔离，Task Capability/Rerun/Replay单元回归也通过；尚不冒称真实网络/数据库创建全链路验收。
- 该过渡保护使用HTTP Basic，只解决当前入口机器身份，目标OAuth/local服务Token仍按[设计7.1](v0.3.0-identity-security-design.md#71-p0过渡止损与目标契约的区别)替换；业务资源/actions权威证明仍待P3。其他internal入口未因此全部完成加固。
- Task/Auth/Agent启动需提供相同独立`TASK_INTERNAL_AUTH_SECRET`（随机文本，至少32字节）；空/过短时服务端503、调用方发请求前失败，不回退用户JWT。默认直连本机8081/8084；跨主机HTTPS或经显式确认的加密网络。模板无真实secret，不生成默认凭据；Task相应客户端不跟随重定向、不记录认证头。

最终两批均构建成功：定向11类57项全执行、0失败/错误/跳过；扩大Common/Auth/Gateway回归46类177项，其中154执行通过、23项历史MySQL迁移测试因未配置专用环境跳过，0失败/错误。两批有重叠，不相加。P0相关8项入口回归现在默认执行并通过，旧探针开关已取消；IdP/BFF/双模式与迁移门禁仍未验收。

最终复核曾补出下游直连编码路径绕过：新增负例在修正前实际得到200而非401；随后将接收方路径匹配与MVC解码/规范化对齐，加入编码/matrix/重复斜杠/点路径单测并在上述最终两批回归通过。没有只依赖Gateway拒绝编码路径来保护下游。

实际验证修正了三个容易漏掉的接入细节：

## 8. 身份映射与跨服务验证增量

- V45在隔离MySQL 5.7验证新装、升级及撤销绑定约束。管理员预绑定使用可信issuer和sub的精确匹配，不根据邮箱合并；Auth查询当前账号状态及本地平台角色。
- OIDC业务服务先验签和校验人类令牌用途，再将同一Access Token发送至Auth本人身份接口；该接口不接受调用方指定其他用户。Auth独立验签、在线检查令牌状态并读取业务用户。身份服务不可用应拒绝请求，不能回退到旧认证。
- 真实Keycloak和隔离MySQL测试覆盖绑定、撤销、禁用、真实Access通过Auth及业务安全链探针；令牌日志脱敏检查通过。真实业务权限服务另有local/OIDC主体的权限对照测试。业务探针不是已部署的完整Document服务或浏览器端到端验证。
- 后续使用独立Auth和Document进程、真实Keycloak及隔离MySQL，对同一用户的空间权限进行双模式HTTP对照：已授权请求返回200且业务成功，缺少权限及非成员返回403，跨模式令牌均返回401。对象存储桶检查使用本机测试替身；该对照不涵盖所有权限，也不代表正式Gateway已切换。
- local服务证明、双签名域互拒及刷新/注销竞争均有隔离原型；Redis条件写入避免测试中的注销后会话复活。这些证据不代表生产Gateway已实现刷新并发控制，也不代替实际部署验收。
- [跨进程恢复原型](../../backend/gateway-service/src/test/java/com/agentdoc/gateway/poc/P0RedisProcessRestartTest.java)使用两个独立Java进程和真实Redis：第一个进程保存加密测试Session与AuthorizedClient并退出，第二个进程恢复并校验。此结果不等同正式Gateway或容器重启验收。
- 真实Keycloak刷新后注入保存异常，测试原型在Redis可用时删除会话并验证后续请求被拒绝；与单进程并发协调、真实Redis注销竞争一起形成P0可行性证据。真实Redis不可用、实际多标签请求及正式Gateway恢复仍在后续阶段验证。
